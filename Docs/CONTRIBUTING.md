# Contributing

## 1. Scope

Contribution guidelines apply to source code, documentation and future module development.

## 2. Before Contributing

Review:
- PRD.md
- ARCHITECTURE.md
- MODULE_SYSTEM.md
- DEVELOPMENT.md

## 3. Code Principles

- Prefer clear, maintainable Swift.
- Keep responsibilities separated.
- Avoid unnecessary dependencies.
- Preserve macOS 12 compatibility.
- Do not modify source media destructively.
- Keep Core independent from optional modules.

## 4. Changes

Changes should be focused and documented when they affect:
- Product behavior
- Architecture
- Project format
- Module API
- User workflow
- Compatibility

## 5. Testing

Contributors should add or update tests for meaningful behavior changes.

## 6. Modules

New modules should use the defined module interfaces and design system.

## 7. Pull Requests

A pull request should explain:
- What changed
- Why it changed
- How it was tested
- Any compatibility impact
- Any project-format impact

## 8. Documentation

Documentation is part of the implementation. Architecture or product decisions should not exist only in code.
